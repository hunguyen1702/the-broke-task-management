Adaptive Repository Harness

Bảy category phối hợp thành một hệ điều hành cho agent: luật ổn định ở ngoài, suy luận và workflow linh hoạt ở trong.

Pattern vận hành

  • Instructions định nghĩa invariant.
  • Router chọn playbook theo risk và uncertainty.
  • Artifacts giữ state; gates và hooks kiểm soát commitment.
  • Evidence xác minh kết quả; learning cập nhật harness.

Implementation surface

Instructions · skills · memory/artifacts · hooks/checks · conditional subagents

1 · Constitution — viết hẳn luật repository 
# Repository Constitution

## Sources of truth
1. Approved product behavior nằm trong `docs/epics/`.
2. Implementation scope nằm trong `docs/tasks/`.
3. Code và tests mô tả implementation hiện tại.
4. Khi các nguồn mâu thuẫn, agent báo conflict; không tự chọn.

## Architecture
- CLI chỉ xử lý parsing, presentation và process exit.
- Business rules và persistence thuộc `tbtm-core`.
- Core operations phải test được mà không khởi chạy CLI.
- Mọi SQLite aggregate mutation phải transactional.

## Authority
- Agent tự quyết implementation detail trong approved contract.
- Agent không tự thay đổi observable product behavior.
- Thay đổi PRD hoặc approved contract cần user xác nhận.
- Spike không tự động trở thành production code.

## Verification
- Rust changes phải qua format, lint và tests.
- UI changes phải có evidence cho relevant states.
- “Done” phải dựa trên test, command hoặc observation.

## Learning
- Failure lặp lại được xem xét chuyển thành test, lint hoặc instruction.
- Rule chỉ liên quan một task không được đưa vào Constitution.

Placement: docs/harness/constitution.md là bản canonical. AGENTS.md và CLAUDE.md chỉ làm adapter bắt agent đọc nó; README.md chỉ giới thiệu cho con người.

# AGENTS.md entry point
Before choosing or executing a workflow:
1. Read `docs/harness/constitution.md`.
2. Classify the request using `docs/harness/router.md`.
3. Load only the selected playbook.
4. Preserve state in the required artifacts.
2 · Router — agent tự chọn workflow 
# Workflow Router

Direct change
- Có approved precedent gần.
- Behavior đã rõ; uncertainty thấp; dễ đảo ngược.
→ Load `playbooks/direct-change.md`.

Research first
- Chưa rõ code flow, ownership hoặc behavior thực tế.
→ Load `playbooks/research.md`.

Explore
- Problem rõ nhưng có nhiều observable solution hợp lệ.
→ Load `playbooks/explore.md`.

Spike
- Một technical/design unknown đang chặn responsible plan.
→ Load `playbooks/spike.md`.

Implementation plan
- Behavior và boundaries đã thống nhất.
- Không còn architecture-changing unknown.
→ Load `playbooks/implementation-plan.md`.

Agent report: Selected route: research → plan, kèm evidence ngắn; agent được reroute khi phát hiện dữ kiện mới.

6 · Risk Gates — review theo hậu quả 
Human approval required before:
- Changing observable product behavior.
- Updating an approved contract.
- Choosing hard-to-reverse architecture.
- Promoting spike code into production.
- Expanding approved scope.

Independent review required before:
- Marking a high-risk plan ready.
- Completing migration or concurrency work.
- Claiming behavior not covered by objective checks.

Đổi private helper hoặc thêm test theo precedent không cần gate. Gate dựa trên commitment và blast radius, không dựa trên số vòng chat.

7 · Proof of Work — “done” phải có bằng chứng 
## Rust implementation
- `mise run format`: passed
- `mise run lint`: passed
- `mise run test`: passed
- New behavior covered by named test.
- Public contract changed: no.
- Remaining assumptions: none.

## Spike
- Blocking question recorded.
- Experiment and fixture retained.
- Result reproduced.
- Outcome: supported with constraints.
- Prototype remains isolated.
